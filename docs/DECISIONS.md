# Decision Log

ADR-style record of the decisions that shape this platform.

## ADR-001 — Pure native clients, no cross-platform UI

**Decision:** Two first-class native apps — Kotlin/Jetpack Compose and Swift/SwiftUI. No Flutter, no React Native, no Kotlin Multiplatform UI. Shared logic via KMM only *where useful*, never for UI.

**Why:** Platform-native UX quality is the product differentiator; "premium intelligent editorial UI" requires native motion systems (springs, shared-element transitions, gesture-driven sheets).

## ADR-002 — Monorepo with contract-first API

**Decision:** One repo: `android/`, `ios/`, backend (root Next.js), `shared-contracts/openapi.yaml` as the single API truth.

**Why:** Atomic cross-platform changes, single CI surface, contract prevents client/backend drift.

## ADR-003 — GitHub Actions is the build farm

**Decision:** The Linux sandbox authors code; GitHub Actions compiles. Android on `ubuntu-latest`, iOS on `macos-14` (free for public repos), backend on `ubuntu-latest`.

**Why:** No local Xcode/Android SDK. Wrapper bootstrapped in CI (`gradle wrapper`); iOS project generated by XcodeGen in CI (no `.pbxproj` merge conflicts ever).

## ADR-004 — SSE first, WebSocket where interrupt matters

**Decision:** Default streaming via SSE. WebSocket reserved for stop-generation, live tool updates, and full-screen voice mode.

**Why:** SSE is simpler, auto-reconnecting, HTTP-native. The product blueprint requires client-to-server mid-stream input for those features only.

## ADR-005 — OPEN: Bring-Your-Own-Key vs platform-only keys

**Status:** ⚠️ Open decision (blocks auth/billing/routing design).

**Recommendation:** Platform-managed keys for MVP (simpler auth, metered billing, safety control), BYOK as a gated Phase-2+ feature with strict key storage (Keystore/Keychain, never server-side plaintext).

## ADR-006 — XcodeGen for iOS project generation

**Decision:** `ios/project.yml` is the source of truth; `GSApp.xcodeproj` is generated in CI and never committed.

**Why:** Hand-merged `.pbxproj` files are a classic multi-dev failure mode. Xcode diffs live in readable YAML.

## ADR-007 — Editorial design system from day one

**Decision:** Both platforms seed a shared visual language: layered surfaces, subtle tonal steps, deep-black/navy dark mode, serif display type for editorial voice, sans for UI, copper accent. Forbidden: cheap gradients, heavy glass, generic Material default.

**Why:** Consistency across 100+ future screens starts with tokens, not screens.

## ADR-008 — The Explore page's floating dock is a page-scoped overlay

**Decision:** The Explore reference mock paints a bottom floating dock (Home / lit Explore pill / Settings). It ships as `ExploreDock` on both platforms — an overlay mounted inside the Explore page only. The drawer remains the app's section switcher and the navigation contract is untouched: Home pops the pushed path to the root, Settings is a plain push. The rest of the app still has no tab bar.

**Why:** The user's production reference is the parity contract for this page, and the earlier frozen stance ("no tab bar anywhere", AppRouter comment) predated it. An overlay keeps the decision reversible — one file per platform — where a global tab-bar shell would have rewritten NavigationStack/NavHost and invalidated the pixel-gated Home dock in the same cycle.

**Consequences:** `AppRouter.swift`'s section-roots comment, both page header comments, and this ADR record the exception together, so the stale-comment drift that once got Explore deleted as "fake padding" cannot repeat.
